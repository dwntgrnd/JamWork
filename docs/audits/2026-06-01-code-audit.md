# JamWork v2 — Comprehensive Code Audit

**Date:** 2026-06-01
**Commit audited:** `c11af59` (branch `main`)
**Auditor:** Read-only static + dynamic review (no code modified)
**Purpose:** Feed future refactoring, cleanup, and hardening planning. This report only documents findings and recommendations — no code was changed.

---

## 1. Executive Summary

JamWork v2 is a self-hosted task/project management app: a **React 19 + TypeScript SPA** (`client/`, ~12.6K LOC) and a **PHP 8.2 / Slim 4 REST API** (`api/`, ~4.9K LOC) on **MySQL 8**, deployed same-origin behind Apache.

**Overall posture is good.** The security fundamentals are notably solid — parameterized SQL throughout (no injection found), bcrypt cost-12 hashing, a 256-bit JWT secret generated by the installer, HttpOnly/SameSite/Secure cookies, anti-enumeration auth responses, hashed single-use password-reset tokens, and HTML-escaped email templates. There is **no dead/orphaned code of note**, no `TODO`/`FIXME` debt markers, and TypeScript compiles clean.

The real opportunities are concentrated in two areas:

1. **Maintainability** — a handful of 1,000+ LOC "god files," a fragile global `window`-event state-sync bus, and no shared data-fetching layer (loading/error logic is hand-duplicated across ~18 components).
2. **Operational hardening** — a vulnerable `firebase/php-jwt` version, outdated/vulnerable npm packages (notably Vite dev-server CVEs), no JWT/session revocation, IP-only rate limiting that breaks behind a reverse proxy, no CI, and near-zero automated test coverage.

> **Note on prior assumptions:** Several concerns from the initial scan did **not** hold up under source verification and were downgraded or removed — see [§10 Corrections](#10-corrections-to-initial-assumptions). Notably: security headers *are* present, the JWT secret *is* strong in real deployments, temp-password entropy *is* adequate, `.env` was *never* committed, and there is *no* SQL injection.

**Top 5 priorities:**

## 3. Security Findings

Severity reflects the app's intended **single-tenant, same-origin, self-hosted** deployment model.

### 3.1 High

**S1 — `firebase/php-jwt` vulnerable (CVE-2025-45769) [Confirmed]**
`composer audit` flags the pinned `firebase/php-jwt` (advisory `GHSA-2x45-7fc3-mxwq`). This library backs all authentication (`api/src/Lib/Auth.php:26,33`).
→ **Fix:** `composer update firebase/php-jwt`, re-test login/refresh, ship in next release.

**S2 — Vulnerable frontend dependencies [Confirmed]**
`npm audit` reports **12 vulnerabilities (5 high, 7 moderate)**:
- **Vite 7.0.0–7.3.1** (high) — path traversal, arbitrary file read via dev-server WebSocket, `server.fs.deny` bypass. *Dev-server only; not shipped in the `dist/` bundle, so production exposure is limited — but anyone running `npm run dev` is exposed.*
- `postcss <8.5.10` (moderate, XSS in stringify), `qs` (DoS), `picomatch` (ReDoS) — all build-time/transitive.
→ **Fix:** `npm audit fix`; review the larger jumps in `npm outdated` (Vite 8, ESLint 10, TS 6) on a branch.

### 3.2 Medium

**S3 — No JWT/session revocation [Confirmed]**
`api/src/Lib/Auth.php` issues stateless HS256 JWTs with a 30-day cookie (`COOKIE_MAX_AGE`, line 12). `AuthMiddleware` (`api/src/Middleware/AuthMiddleware.php:38-42`) slides the expiry on every request older than 24h, so an actively-used token's lifetime is effectively unbounded. There is no server-side token store, `jti`, or token-version column. Consequences:
- **Password change / reset does not invalidate existing sessions** (`change-password`, `reset-password`, `set-new-password` only update the hash).
- **Logout** (`AuthRoutes.php:307`) clears the cookie client-side only; a copied token stays valid.
- An admin **deleting a user** does not invalidate that user's outstanding token until it naturally expires.
→ **Recommendation:** Add a `token_version` (or `password_changed_at`) column to `users`, embed it in the JWT, and reject tokens whose version is stale. Bump it on password change and admin delete.

**S4 — Rate limiting is IP-only and not proxy-aware [Confirmed]**
`api/src/Middleware/RateLimitMiddleware.php:40` keys solely on `REMOTE_ADDR`. Behind a reverse proxy / load balancer (a common self-host setup), `REMOTE_ADDR` is the proxy IP, so **all users share one bucket** (false 429s) and the per-IP login throttle is defeated. Storage is also file-based in `sys_get_temp_dir()` (line 21) — single-server only, with a known small race on concurrent `file_put_contents`.
→ **Recommendation:** Read a trusted, configurable forwarded-for header when behind a proxy; document the single-server assumption; consider an APCu/Redis backend for multi-instance deployments. (Comment on line 30 says "10 requests" but code allows 20 — fix the comment too.)

**S5 — Missing CSP and HSTS headers [Confirmed]**
Root `.htaccess` *does* set `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, and `X-XSS-Protection: 0` — good. **Not present:** `Content-Security-Policy` and `Strict-Transport-Security`.
→ **Recommendation:** Add a CSP (the SPA uses no inline-eval, so a reasonably strict policy is feasible) and HSTS (assuming TLS-only deployment).

### 3.3 Low

**S6 — Login timing oracle enables user enumeration [Confirmed]**
`AuthRoutes.php:279` short-circuits: `if (!$user || !Auth::verifyPassword(...))`. When the email doesn't exist, the (deliberately slow) bcrypt verify is skipped, so a missing user responds measurably faster than a wrong password — defeating the otherwise-careful anti-enumeration design.
→ **Recommendation:** Always run a bcrypt comparison against a dummy hash when the user is absent.

**S7 — `GET /auth/users` exposes all users to any authenticated user [Confirmed]**
`AuthRoutes.php:528-548` returns every user's id, email, role, and created_at to any logged-in member (only `AuthMiddleware`, not `AdminMiddleware`). Likely intentional for assignee pickers, but it does leak the full email roster to every member.
→ **Recommendation:** Confirm this is intended; if so, document it. Otherwise scope the fields or gate behind admin.

**S8 — Admin-supplied invite password bypasses length policy [Confirmed]**
`AdminRoutes.php:54` accepts an optional `data['password']` with no validation, bypassing the `min:10` rule enforced everywhere else.
→ **Recommendation:** Validate the optional field, or remove it and always auto-generate.

**S9 — Inconsistent escaping in invite email [Confirmed]**
`Mailer.php:60` interpolates `{{WORKSPACE_NAME}}` **without** `htmlspecialchars()`, whereas every other template method (e.g. lines 98, 137) escapes it. The workspace name is admin-controlled, so risk is low, but the inconsistency is a latent stored-XSS-in-email vector.
→ **Recommendation:** Escape `$workspaceName` in `sendInviteEmail` for consistency.

**S10 — `set-new-password` bcrypt-loops over all valid tokens [Confirmed]**
`AuthRoutes.php:134-150` loads every non-expired, unused reset token and `password_verify()`s the candidate against each. Tokens are short-lived and few, so impact is minimal, but it's an O(n) bcrypt cost driven by outstanding tokens.
→ **Recommendation:** Acceptable as-is; if reset volume grows, store a fast lookup key (e.g. token prefix) alongside the hash.

### 3.4 Informational

- **CSRF:** No anti-CSRF tokens on the JSON API; protection relies on `SameSite=Lax` cookies. Since all mutations are non-`GET` and `Lax` blocks cross-site `POST/PUT/DELETE`, this is acceptable for the deployment model. Worth a documented decision. The installer (`install.php`) *does* use proper CSRF tokens + `hash_equals`.
- **`$_ENV['APP_ENV']` accessed without default** in `api/index.php:39` — emits a notice if unset; `addErrorMiddleware` then defaults `displayErrorDetails` to false (safe), but tidy this up.
- **`.htaccess` hardening is good:** denies `.env`, `composer.*`, `.installed`, and `src/`/`migrations/`/`vendor/` directories.

## 4. Refactoring Candidates

### 4.1 God files (decomposition targets) [Confirmed via `wc -l`]

| File | LOC | Concern |
|------|-----|---------|
| `client/src/pages/sprints.tsx` | 1,638 | Sprint planning UI + sorting + filtering + dialogs + mutations in one component |
| `client/src/components/task-list.tsx` | 1,329 | Table render + selection + inline edit + keyboard nav + fetching |
| `client/src/components/timeline-view.tsx` | 1,258 | Gantt render + zoom + drag-drop + date math + dialogs |
| `client/src/components/task-drawer.tsx` | 1,119 | Create/edit + subtasks + links + auto-save |
| `api/src/Routes/TaskRoutes.php` | 1,118 | All task CRUD + bulk + reorder + subtasks in one route class |
| `api/src/Routes/AuthRoutes.php` | 551 | All auth endpoints in one class |
| `api/src/Routes/SprintRoutes.php` | 515 | Sprint CRUD + planning + completion |

→ Extract presentational subcomponents (rows, cards, dialogs) and move task/sprint mutation logic into hooks (client) / a model/service layer (API).

### 4.2 Fragile global event bus [Confirmed]

State is synced across components via `window` `CustomEvent`s: **18 dispatch sites, only 3 listeners, 3 event names** (`projects-updated`, `sprints-updated`, `workspace-name-updated`). This is an implicit, untyped, hard-to-trace coupling — adding a consumer means hunting every dispatcher.
→ **Recommendation:** Replace with React Context (or a small store like Zustand) for projects/sprints/workspace state. Highest-leverage maintainability change.

### 4.3 No data-fetching abstraction [Confirmed]

**18 components declare their own loading state and 8 their own error state**, each repeating the `useEffect` → fetch → `setLoading`/`setError` pattern. No caching, dedup, or retry. The API client itself (`client/src/lib/api.ts`) is clean (`apiGet/apiPost/apiPut/apiDelete`) but unwrapped.
→ **Recommendation:** Adopt TanStack Query (or a thin custom `useResource` hook) over the existing `api.ts` helpers.

### 4.4 Duplicated/inline validation in routes [Confirmed]

`TaskRoutes.php:95-110` (and peers) hand-roll `in_array` enum checks and UUID regex inline, duplicating capabilities already in `Validator` (`api/src/Lib/Validator.php`, which has `in:`, `uuid`, `uuid_array` rules).
→ **Recommendation:** Route all field validation through `Validator` for one source of truth.

### 4.5 No React error boundaries [Confirmed — `grep` found none]

Any render-time exception white-screens the whole SPA.
→ **Recommendation:** Add an `ErrorBoundary` around the routed layout (`protected-layout.tsx`).

## 6. Code Quality & Consistency

- **ESLint: 72 errors / 4 warnings** (`npm run lint`), categorized:
  - `no-unused-vars` ×10, `no-explicit-any` ×9, `react-hooks/exhaustive-deps` ×4, `react-refresh/only-export-components` ×2, `react-hooks/immutability` ×2, `set-state-in-effect` ×1, `no-useless-escape` ×1 (`reset-password.tsx:36`).
  - → The lint config is healthy; the codebase just isn't lint-clean. Wire `npm run lint` into CI and fix the backlog.
- **Type safety:** 37 occurrences of `any`/`@ts-ignore` (mostly `catch (err: any)` and event handlers). `tsc -b` passes clean. → Replace `any` in catch blocks with `unknown` + narrowing.
- **Logging:** 36 `console.*` calls — **all `error`/`warn`, zero `console.log`** (good discipline). Consider a tiny logger wrapper if you later want to silence these in production.
- **Error handling:** No empty catch blocks found. API routes use consistent try/catch + transaction rollback (e.g. `AdminRoutes.php:386-416`). Client catches mostly log to `console.error`; no user-facing retry.
- **Debt markers:** **Zero** `TODO`/`FIXME`/`HACK`/`XXX` across all source — clean, though it means no inline tracking of known gaps.
- **Tests & CI — the biggest gap:**
  - **No CI/CD** (no `.github/workflows`, no pipeline).
  - **One** test file: `api/tests/NotificationServiceTest.php`, a self-contained harness run via `php tests/NotificationServiceTest.php`. `composer.json` has **no `require-dev`, no PHPUnit, no test script** — so it isn't part of any runnable suite.
  - **No frontend test framework** at all (no Vitest/Jest/Playwright).
  - → Stand up Vitest (client) + PHPUnit (api), wire both plus `lint`/`tsc` into CI. Prioritize tests around auth, the notification send-rule, and task mutations.

## 9. Strengths (Keep Doing This)

- **No SQL injection** — every query is parameterized; `buildInClause` (`TaskModel.php:14`) emits `:tid0, :tid1…` placeholders and dynamic SET clauses draw column names from hardcoded maps (`TaskRoutes.php:113`). PDO runs with `ATTR_EMULATE_PREPARES = false`.
- **Strong auth crypto** — bcrypt cost 12; installer generates a 256-bit JWT secret (`install.php:809`); HttpOnly + SameSite=Lax + Secure(prod) cookies.
- **Careful password-reset flow** — 32-byte URL-safe tokens, bcrypt-hashed at rest, single-use, 1-hour expiry, prior tokens invalidated on new request.
- **Anti-enumeration** responses on forgot-password and login (timing nuance in S6 aside).
- **Safe rendering** — no `dangerouslySetInnerHTML`, `eval`, or `innerHTML`; React auto-escaping; email templates use `htmlspecialchars`.
- **`NotificationService`** — exemplary: documented to a PRD, pure decision functions, unit-tested, never throws into the caller.
- **Clean foundations** — centralized style tokens & date utils, consistent TypeScript (no stray JS), `tsc` passes, no orphaned files, zero debt markers, sensible `.htaccess` hardening.

## 10. Corrections to Initial Assumptions

For planning accuracy, these earlier-scan concerns were **disproven** during source verification and should not drive work:

| Claimed | Reality |
|---------|---------|
| "Security headers all missing" | X-Frame-Options, nosniff, Referrer-Policy, X-XSS-Protection **are set** in root `.htaccess`. Only CSP + HSTS missing (S5). |
| "Default JWT secret may ship to prod" | Installer generates a **256-bit** secret (`install.php:809`); the dev default is dev-only. |
| "Temp passwords have low entropy (~42 bits)" | `bin2hex(random_bytes(8))` = **64 bits**, adequate, and `must_reset_password=1` forces a change. |
| "`api/.env` committed (secret leak risk)" | **Never tracked**; `git log --all -- api/.env` is empty; correctly gitignored. |
| "Dynamic query building → injection risk" | **Fully parameterized**; no injection (see §9). |
| "36 `console.error` to clean for prod" | All 36 are `error`/`warn` (legitimate); **zero** `console.log`. |
| "Several underutilized/orphaned components" | All are referenced; no orphaned files exist (§5). |
